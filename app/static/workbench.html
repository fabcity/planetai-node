Sensors workbench

Flash and test a sensor

Put the firmware on a Bayu sensor or a Meshtastic radio from this page, then connect it by USB and watch each of its sensors work, live, with what it is reaching: WiFi, a broker, the mesh. Several boards at once is fine. Opened from a PLANETAI node, the same page draws every device that node reads. A USB cable and Chrome or Edge on a laptop; nothing to install, and it keeps working offline once opened.

01 · The sensor

The Bayu sensor

The Bayu is Fab Lab Bali's sensor, the Making Sense Bali DIY node. The button installs the newest Bayu firmware on a Seeed XIAO ESP32-S3 or an ESP32-C3 SuperMini, and the firmware finds whichever sensors are plugged in at boot: HM3301, Sensirion SEN5x, BME680, PMS5003, SHT4x, SCD4x. On Seeed's Expansion Base it also uses the screen, the buzzer and the microSD. The page detects the chip, so there is one button.

Bayu · DIY node

Flash the sensor

Plug the board in with a data cable (a charge-only cable shows nothing). If no port appears, hold BOOT while plugging in. Press the button, pick the port, and let it run: about a minute. Then go to Test.

This browser cannot open a USB port. Use Chrome or Edge on a laptop. Phones, Safari and Firefox do not support Web Serial.

The firmware image could not be read from Making Sense Bali's firmware folder. Check the connection, or flash from the Arduino IDE as the build guide describes.

Reflashing keeps the sensor's saved WiFi, token and name. A sensor that has never been set up opens its setup portal on first boot.

Then, once

  1. For Smart Citizen, the setup tool. Open makingsense.fablabbali.com/setup.html on your phone. Sign in (no account yet? create one on smartcitizen.me), name the sensor and say where it hangs: the tool creates it on the platform with its token. Then it hands the token to the sensor: join the sensor's WiFi MSB-Node-xxxx (password makingsense) and scan the code it shows. Pick your home WiFi in the portal, press Save, and the tool waits for the first reading.
  2. On your phone, join the WiFi network MSB-Node-xxxx, password makingsense. The setup page opens; if it does not, browse to 192.168.4.1.
  3. Give the sensor your WiFi, a name, the site, the mounting height, and tick indoors if it hangs in a room.
  4. Where it publishes. For Smart Citizen, the setup tool has put the token in already: leave the broker blank. To send readings to a PLANETAI node in the house instead, type what planetai broker prints on that machine:
Broker host
the node machine's .local name or LAN address
Port
1883
User
planetai
Password
printed by planetai broker
Token
the token the setup tool gives, or any six characters if the node is the only reader

Only the token ever reaches Smart Citizen. Name, site and height stay on the sensor's own status page.

02 · The radio

Meshtastic radios

Keep every radio in a mesh on the same firmware version. Radios on different versions stop hearing each other, and nothing tells you. This is the stable release the PLANETAI nodes run. The ESP32 boards flash from here, the nRF52 boards take a file copied to a drive.

ESP32-S3 · gateway or sensor node

XIAO ESP32-S3 + Wio-SX1262

Meshtastic firmware is per board and the job is a setting, so the same image does for a gateway or a sensor node. As the gateway it is the mesh's door to the node. As a sensor node, the Bayu with a radio, it carries an I2C sensor where the reading is wanted. It has no GPS, so the node gives it a fixed position when it is provisioned. The flasher erases it and installs the release, and the radio comes up with no region and no channel, because those come from the node.

This browser cannot open a USB port. Use Chrome or Edge on a laptop. Phones, Safari and Firefox do not support Web Serial.

Antenna on before power, always. Never use the phone app's over-the-air update on this board: Seeed says it can brick it.

ESP32-S3 · gateway or sensor node

Heltec WiFi LoRa 32 V3

The small one with a screen. It has WiFi, so it can be the gateway the same way the XIAO is. It has no GPS, so as a sensor node it gets a fixed position from the node. The flasher erases it and leaves it with no region and no channel, those come from the node.

Antenna on before power, always. This image is for the V3 only, a V4 needs its own and this page does not have it.

Nobody on the team has run this board with a PLANETAI node yet.

ESP32 · sensor node with GPS, or gateway

LilyGO T-Beam

It has GPS and WiFi, and takes an 18650 battery. As a sensor node it knows where it is, so it needs no fixed position, and it can be the gateway too. The flasher erases it and installs the release.

Antenna on before power, always. This is the T-Beam v1.x, with an ESP32. The T-Beam Supreme has an ESP32-S3 and needs another image, which this page does not have.

Nobody on the team has run this board with a PLANETAI node yet.

nRF52840 · field sensor

Wio Tracker L1 / L1 Lite

No WiFi, GPS, a Grove port for a 3.3 V sensor, a battery. Double-click RST: a drive appears. Copy the file onto it and the radio reboots on its own.

Download .uf2

On macOS 26 the copy fails (error -36). Use serial DFU instead: adafruit-nrfutil dfu serial --package <ota.zip> -p /dev/cu.usbmodem… -b 115200 --singlebank. ota.zip

nRF52840 · shelf radio

SenseCAP T1000-E

The card-sized one, paired to a phone: it receives the node's alerts when the internet is down. Same route: double-click the button, a drive appears, copy the file.

Download .uf2

ota.zip for serial DFU, as for the Tracker.

nRF52840 · field sensor, soil

RAK WisBlock RAK4631

The WisBlock core, on a RAK base board. This is the one for soil, the RAK12035 soil moisture sensor only works on RAK boards. No WiFi, and GPS only with a RAK12500 module on the base, without it give the radio a fixed position when you provision it. Double-click RST: a drive appears, copy the file.

Download .uf2

ota.zip for serial DFU, as for the Tracker. If no drive appears after the double-click, the bootloader is old, use this one.

Nobody on the team has run this board with a PLANETAI node yet.

nRF52840 · shelf or pocket radio

LilyGO T-Echo

It has GPS and an e-ink screen, and comes in its own case with a battery. Paired to a phone it does what the T1000-E does on a shelf, and you can carry it around to see where the mesh reaches. Double-click the reset button: a drive appears, copy the file.

Download .uf2

ota.zip for serial DFU, as for the Tracker.

Nobody on the team has run this board with a PLANETAI node yet.

Region and channel

A radio with no region never transmits, and nothing tells you. A radio on the wrong frequency slot is outside what the country allows. So this page sets neither: the node operator's QR carries the region, the frequency slot and the mesh's channel keys together, and importing it sets all three at once.

  1. Open the Meshtastic app and connect to the radio over Bluetooth (PIN 123456 on radios without a screen).
  2. Scan the QR the node operator shows you, from planetai radio url on the node. Accept replacing the channels. Region, slot and keys are done.
  3. Or skip the phone: plug the radio into the node and run planetai radio provision sensor "Subak edge" SBK --port …, with --fixed LAT,LON for a board with no GPS, like the XIAO, the Heltec or a RAK without its GPS module. Same result, and the node remembers the radio.

Bali runs SG_923 with the slot pinned inside 920 to 923 MHz, Menorca EU_868, Boston US. Whoever runs the node has made that choice; a radio only copies it.

Why the page cannot flash the nRF52 boards

The nRF52 boards do not take firmware over a serial port. They show up as a USB drive and take a file, and copying a file onto a drive is something no browser button can do for you. The ESP32 boards do take firmware over serial, which is what the flash buttons on this page use.

Every file here is the one in the Meshtastic release, unchanged, checked against the release's own checksums and kept on this site.

For a workshop with a weak connection

Keep every firmware image and the flasher on this computer, once, while the internet works. Then this page flashes and tests with no connection at all.

Nothing connected yet

Plug the board in with a data cable and press Connect. Pick the port that says USB JTAG/serial or usbmodem. No board at hand? The demo plays two Bayu sensors and a node, every one marked DEMO.

A browser cannot scan a network. This map is what the node knows: every sensor that publishes to it, every radio its gateway hears, the platforms and stations it reads, the nodes it lists. And the boards on this computer's USB, with every mesh node a radio on USB hears.

A PLANETAI node

A node answers this page when the page comes from the node itself (its address, then /workbench), or from this machine. A token lets it show everything at SHARE_LEVEL=off; planetai ui prints it.

The USB port is busy

Another program has this board's port open, so the flasher cannot use it. Close the serial monitor in the Arduino IDE, and any other tab with this page or another flasher, then press Connect and flash again. If it still fails, unplug the board, plug it back in and try once more.
