# Custody vs `local` — decision

**Question.** `local` decides which sensors may make an Index cell say `live`. It means "ours and here". A
child's hourly means are ours and 400 m away, so a community node aggregating ten homes counts zero and can
never say `live`. A peer's sensor may be across the street and is not ours at all.

**Recommendation.** No new column, no data migration: custody is `s.local OR s.kind = 'child'`, plus one
generated column so the predicate is written once rather than in fifteen SQL statements. `local` keeps its
present meaning. Add `kind='peer'`. Drop the `_1h` suffix from the child push so pack SQL matches. Push alert
timestamps to the parent — never message text — and let the parent compute ρ.

**Cost.** Three files of code (`app/index.py`, `app/main.py`, `packs/heat/cells.yml`), one `ALTER` in
`init.sql`, one new endpoint and table for events. No existing row changes classification except `child`,
which changes from wrongly excluded to included. Node #1 is unaffected: same 192 buckets, verified.

**Unblocks.** A community node that can honestly say `live`. ρ that rolls up, so a City node measures the
thing the architecture says only this layer can measure. `planetai publish` in the open, so Santiago can
follow Bali without a private repo.

**Open for Tomas (§3).** May a community node say `live` with no sensor of its own? Recommended yes, with
≥ 2 in-custody sensors from ≥ 2 children.
