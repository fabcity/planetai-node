# The make pack — decision

**Question.** An act alert ends at "shut the kitchen windows". Should the node also be able to say what could be
made to fix the room, and who nearby could make it — and if so, does that knowledge come from a service the node
calls, or from something the node carries itself?

**Recommendation.** A data-and-code pack, `packs/make`, that calls one endpoint on an Open Hardware Manager
instance and nothing else. Rules gain an optional `fabricable:` key — a list of OKH ids or content hashes.
`OHM_URL` defaults to empty, and empty means idle and silent, the way `nearby` treats a missing ring. The node
sends a design id and its own position rounded to three decimals, never its address; it receives designs and
facilities with coordinates, and computes the distance itself, because the hosted instance accepts
`location_coords` and does not act on it. One `sensors` row per design, `kind = 'external'`, no readings, which is
both the store and the offline cache. One clause in part 4 of the report; one card beside the ring with the
`external` provenance pill; nothing at wall mode. No cell, no `deployed_at`, no LLM call, no OKW export.
Fab Lab Bali first — it is already in the matchable network surface, 3.9 km from node #1 — on the hosted instance
first, then on the lab's own instance on the tailnet with `OHM_FEDERATION_ENABLED` false.

**Cost.** One new pack folder, one comment line in `init.sql` adding `external` to the `kind` list, five
assertions in `tools/check_rules.py`, one clause in `report.sheet()`, one card in `app/static/index.html`, three
settings rows, one test. No new dependency — the pack fetches with the `httpx` client the adapters already share,
and OHM never runs on the node. Two ids to write into `packs/air-quality/rules.yml`, both of which exist today.
The real cost is not in this repo: it is the per-entry work of giving designs an OKH manifest, and the per-lab
work of filling in an OKW `equipment` array. Both are somebody else's week, and neither blocks v0.47.

**Unblocks.** The paper's **Agent-1 workflow** at community scale — PM2.5 over threshold for an hour produces a
bilingual advisory *and* a shortlist of fabricable filters for the lab to approve, which is the half of that
workflow nothing in the node could write. **Stage 3 evidence** in v0.48: once a lab approves a shortlist and a
body raises an OHM RFQ or registers an asset, that id is the `evidence_ref` stage 3 has been waiting for — the
node still never writes it, but the thing it points at now exists. And **things-that-work as one record**: a TTW
entry carrying the same OKH id makes the TTW query skill a skin over this same call, so the response layer is one
identity and one endpoint across a node container and a Cloudflare Worker instead of two systems that agree by
coincidence.

**Open for Tomas.** A design is not a sensor, and this puts it in the `sensors` table because `kind` already
carries portals and models and a new table costs a migration. If that reads wrong, a four-column `fabricable`
table is half a day and changes nothing above §4 of the proposal.
