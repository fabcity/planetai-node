# Next days Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The node keeps 72 hours of every model forecast it reads, for its own territory, and Now gets a "Now · Next
days" switch showing today, tomorrow and the day after per thing it watches, with a pack's own line (surf).

**Architecture:**
- **Revisions:** one insert helper lets a future `fc_` row replace an older value. The `observations` view stops at now.
- **Fetching:** the `forecast` pack fetches BMKG plus three opt-in Open-Meteo sources (weather, CAMS, marine), each on
  its own six-hour stamp. It fetches for a list of territory points chosen by `NODE_SCALE`.
- **Serving:** `GET /forecast` gains `days` (per issue, per local day, judged with the issues' own lines) and `lines`
  (packs' `ahead:` text). The doors page draws them behind a switch.

**Tech Stack:** Python 3.9+, FastAPI, psycopg 3, Postgres/PostGIS, h3, vanilla JS doors; assert-script tests run by
`tests/all`; Playwright visual gate; surf pack in planetai-wild-packs (stdlib + PyYAML + duckdb tests).

**Spec:** `docs/SPEC_next_days.md` (approved 3 Nov 2026, Open-Meteo opt-in).

## Global Constraints

- **Branches:** node work on `next-days-2026-11-03` (worktree `planetai-node-nextdays`, from main b643b79). Pack and
  registry work in planetai-wild-packs, on a new branch `surf-ahead-2026-11-03` from its main (7c1274b).
- **Horizon:** `HOURS = 72`. Fetch interval: `FORECAST_POLL_HOURS` (default 6), now one stamp file per source:
  `out/forecast.<source>.last`. A stamp is touched only after that source's fetch succeeded.
- **Opt-in:** `FORECAST_OPENMETEO` stays default `0`. It gates all three Open-Meteo sources (`forecast-om`,
  `forecast-cams`, `forecast-marine`). Marine runs only while the `coast` pack is on, at the sea point coast snaps to.
- **Metrics:**
  - New: `fc_wind_gusts`, `fc_rain_prob` (%), `fc_shortwave` (W/m²), `fc_et0` (mm), `fc_soil_moisture` (m³/m³),
    `fc_pm25` (µg/m³), `fc_uv`, `fc_wave_m` (m), `fc_swell_m` (m), `fc_swell_s` (s), `fc_swell_dir` (°).
  - All declared like the existing `fc_` ones: `role: derived, comparable: false`. Every source stores
    `fc_lead_hours`.
- **Revision rule:** `ON CONFLICT (sensor_id, metric, ts) DO UPDATE SET value = EXCLUDED.value WHERE EXCLUDED.metric
  LIKE 'fc\_%' AND EXCLUDED.ts > now()`. Only the poll insert and `packs/forecast/fetch.py` use it. MQTT,
  `/readings` and bootstrap keep `DO NOTHING`.
- **observations:** gets `ts <= now()`.
- **Territory:** `home` gives 1 point (the node); `community` the node's res-7 cell plus `grid_disk(…, 1)` (7 points);
  `city` res 6 with `grid_disk 2` (19 points); `region` res 5 with `grid_disk 2` (19 points). The points are cell
  centres, except the node's own cell, which uses the node's lat/lon. Sensor ids: `forecast-om`, `forecast-cams` and
  `forecast-marine` for the node's own point (unchanged ids), `<id>-<cell>` for the others. Every sensor's meta
  carries `cell`.
- **Days:**
  - Local days are taken in NODE_TZ. "rest" runs from the next whole hour to midnight, then come tomorrow and the day
    after.
  - Air is the mean of the day's `fc_pm25` hours, with its `peak` and `peak_at`, judged against the air issue's line.
    Heat is the max of `apparent(fc_temp, fc_humidity)` (the engine's function), judged against the heat issue's line.
  - `state` is "over" or "under" (no near band). `hours_over` counts the hourly values above the line.
  - wind_rain gives `gust` (the day's max `fc_wind_gusts`), `rain_mm` (the sum of `fc_rain`) and `rain_hours` (the
    3-hour block with the most rain, "HH:00–HH:00"). sea gives the max `fc_wave_m`.
- **`ahead:`**
  - The contract is `{id, title: {en, es, id}, sensor, days: [key_d1, key_d2]}`, where the keys are written without
    their locale (`ahead_d1`).
  - The node reads `ahead_<loc>_d1` and `ahead_<loc>_d2` for en, es and id, at most 160 characters each, only while
    the pack is on and the sensor meta's `fetched` equals today in NODE_TZ. The page escapes all of it.
- **Page:**
  - The switch uses the register style (`.reg` / `button.on`), keyed by `#now/next` and kept in localStorage (wrapped
    in try/catch).
  - Use the doors' own card kinds. No new hues. The frozen layer is untouched.
  - The doors phone layout at ≤480 px gets the switch with Now. `mobile.html` is not touched.
- **Copy:**
  - The provenance sentence: "These come from models. The node does not forecast, and nothing here sends a message."
  - With Open-Meteo off: "Air, the sea and more hours come from Open-Meteo, which is off on this node. Turn it on in
    Set up → Packs → forecast."
  - Public docs text is in Tomas's voice (run the avoid-ai-writing pass twice on docs/site text).
- **Tests and lint:**
  - Never import `main` or `agent_loop` in a test; lift functions by AST. Every new suite gets its `tests/all` line
    and the count goes up. Nothing goes after a suite's `sys.exit()`.
  - `make lint` stays green: `check_docs` refuses a doc that names a file that doesn't exist yet, so docs are written
    in the task that creates their files.
- **Commits** end with `Co-Authored-By: Claude <model> <noreply@anthropic.com>`.

## Review Focus

1. **A node that never set `FORECAST_OPENMETEO`.** It is the default case. Next days draws BMKG's weather only
   (where BMKG covers the node), plus the opt-in line. Nothing is blank and nothing fails. Test in Task 5 and Task 7.
2. **A node outside Indonesia (Menorca) with `FORECAST_OPENMETEO=0`.** BMKG has nothing, so `days` has no rows at all.
   The view says why in one line, not an empty grid. Test in Task 5 (fixture with no sources) and Task 7.
3. **A forecast re-fetch where the newer issue lowers an hour's value.** The stored value goes down, a past hour is
   never touched, and a measured row with a future clock is never overwritten. Test in Task 1, on the scratch PostGIS.
4. **Day cuts at midnight local time in Asia/Makassar (UTC+8).** A row at 23:00 local belongs to that day even though
   it is 15:00 UTC. "rest" starts at the next whole local hour. Test in Task 5.
5. **One source's call refused (429) or timed out.** The other sources still fetch and store. The refused one retries
   next poll instead of six hours later. The page shows the sources it has. Test in Task 2.
