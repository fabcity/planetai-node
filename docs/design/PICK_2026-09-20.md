## 4 · The gaps: six the pack named, five it did not

The pack's rule stands — a session that wants a field not on the wire STOPs and lists it. These are the list.

**Named by the data contract, all verified open against node #1 on 20 Sep:**

**Found by this session, none of them scheduled:**

**G · `/settings` rows carry no `default`.** Prompt 4 demands a six-part field row — label · help · value ·
default · when it takes effect · where it comes from. A runtime entry carries `key, group, label, help,
value, set, source, choices, secret, restart, outward`. Five of the six parts are there; **`default` is not
on the wire at all** and cannot be derived from `set` or `source`. Prompt 4's Set up commit STOPs here.

**H · No pack-declared setting reaches `/settings`.** The contract says the `make` keys are "on the wire
since v0.65/v0.66". They are not. The string `MAKE` appears **zero times** in node #1's entire `/settings`
payload. The `packs` group on the wire holds exactly two keys: `PACKS_ENABLED` and `PACKS_ALLOW_CODE`.
This is not the pack being off — node #1's `.env` has **`MAKE_ENABLED=1`**, the keeper turned it on, and
the keys are still absent. Pack-declared settings simply do not reach `/settings`. Prompt 4's Packs group
has nothing to draw, and no keeper can turn a pack on from Set up.

**I · The facility row carries one of its seven `meta` fields.** The contract promises
`meta.{distance_km, capabilities, url, snapshot, fetched, attribution, registry_slug}`. Node #1's one
facility row is:

```
{"sensor_id":"lab-fablabbali","source":"fablabs-io","name":"Fab Lab Bali","lat":-8.793,"lon":115.15,
 "indoor":false,"local":false,"custody":false,"kind":"facility","scale":"community","cadence":"P30D",
 "meta":{"attribution":"fablabs.io — Fab Lab Network. Not openly licensed; see registry_slug."}}
```

`attribution` and nothing else. Prompt 3's *where to go* row — "name · km in the mono · up to three
capabilities · the snapshot filename as the date · the word `cached`" — can draw the name and `cached`.
The distance is not there and must not be re-derived from `lat`/`lon`: the whole point of gap F is that the
pack owns the wording and the distance. `capabilities` cannot be derived at all. **Gap I is larger than
gap F and blocks the same row**: F is a missing sentence, I is the missing facts under it.

**J · `planetai snapshot` cannot make a fixture the node can replay.** **— FIXED 21 Sep, before prompt 1.** The snapshot tool is
endpoint-driven — twelve paths, `/health /issues /stats /alerts /rho /cells /observations /sensors /trust
/report/latest /nearby /forecast` — and writes each body under its own key. `engine.Replay.TABLES`
(`app/issues/engine.py:724`) answers the engine's five queries from `stats`, `observations`, `alerts`,
**`actions`** and **`readings_1h`**. Three arrive by luck of naming. The last two are not endpoints and are
never captured, and `Replay.execute` reads `snapshot.get(key) or []`, so a fixture missing them does not
raise — **it replays hollow**: no act ledger, no stages, no series, no buckets, no barcode.

The committed `node1-2026-09-06.json` has both tables because it was hand-assembled (its README says parts
were transcribed and reconstructed). Every fresh snapshot since has been silently unrenderable. The
README's line "To make another one, on the node: `planetai snapshot --out <file>`" is wrong today.

**How it was fixed.** `readings_1h` needed no new route: `GET /aggregates` already returns that table, short
only the three columns (`indoor`, `local`, `kind`) the engine joins in from `sensors`, so the snapshot joins
them from `/sensors` rather than widening a route other nodes federate on. `actions` had no read route at all
— `/actions` was POST only — so one was added, on neither share allowlist, because `actor` and `note` are the
household's own words about their own house. `/alerts` is now asked for 200 rows, which is what
`engine._read` itself reads; it was asking for 50, so every fixture replayed a shorter ledger than the node
it came from.

And the half that mattered more than either: `Replay.execute` read `snapshot.get(key) or []`, so an **absent**
table and an **empty** one were the same fact. They are not. A node with nothing to report sends `[]`; a
snapshot that never fetched sends no key. The absent case now raises, `api.fixture()` already turns that into
an honest body, and `tests/test_issues_engine.py` checks both halves — that a missing table refuses, and that
every file in `app/issues/fixtures/` carries all five. Verified by reverting the fix and watching the test go
red on all five tables.

The v0.66 snapshot taken for this round stays a **wire-shape fixture** — it was taken before the fix and
cannot replay — and has moved to `docs/design/fixtures/`, which is where evidence of the wire belongs. It
remains the only record of `/sources`, the facility row and the v0.66 `/settings` shape. A replayable v0.66
fixture needs node #1 on v0.67 first.

**K · The four-distance vocabulary is still split**, as the contract says. `/issues.labels.en` is
`{room, yard, ring, region}`; the sentences say *the wall outside · the street · the model*. Confirmed on
the wire. Decision 1 below stands.

Per `docs/NEXT_RELEASE.md` rule 3 the page ships alone. **A, C, F, G, H and I are node-side and go out in
a release before the page's** — six still owed, plus J, which is done. J went first, because without it no
later prompt could render what it builds against a current node.
