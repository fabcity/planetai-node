## Summary: the five findings that would mislead a stranger fastest

1. **The token canon the brief names for the landing is not in either repo.** `#F9F5F2`, `#171717` and `#E4E2DD` appear zero times across every HTML and CSS file in `planetai` and `planetai-node`. The landing, the observatory, node0 and the timeline all use the FCI values `#F7F5F1` / `#1E1E1E`. Decision 0 is therefore not a choice between two live systems. It is a choice between the one system that is deployed everywhere and one that is deployed nowhere.

2. **The landing's provenance pills are not provenance.** `planetai/index.html:1924` renders `<span class="prov-pill p-live">Commitment</span>`, coloured with `--prov-live` (`#00A057`, the same green as a fetched-this-session value). A promise to publish null results wears the badge that elsewhere means "this number was measured". Line 1920 gives "Calibration required" the same green through `--L4`. A reader who has learned the pill on any other surface reads a commitment as a measurement.

3. **The dashboard paints an unhealthy number in the clean colour on an empty node.** `app/static/index.html:384` computes `grade(iv ?? ov)`; with no indoor and no outdoor sensor both are null, `grade` returns null, and `HUES[null] || HUES.clean` falls through to `#7AC943`. On `pai-clean` the hero reads "The model says **53** for this square of the map" with the 53 in clean green. 53 µg/m³ is over three times the WHO daily guideline the same page draws as a red line. Screenshot: `shots/dashboard-clean/1440x900/now.png`.

4. **The wall view prints the wrong unit.** `app/static/index.html:332` is `<div class="eye">Inside · µg/m³ · PM2.5</div>` inside a rule with `text-transform:uppercase`. Chrome uppercases U+00B5 to Greek capital Mu, which reads as M. The wall screen in a house says **MG/M³**, a thousand times the actual unit. Screenshot: `shots/dashboard-node1/1440x900/wall.png`.

5. **node0 publishes a ρ that is wrong by a third.** `planetai/node0/index.html:318` says `0.67` and "twelve alerts that asked for something, eight answered". `GET /rho` on node #1 at 2026-09-06T14:08:06Z returns `{"window_days":30,"alerts_act":28,"acted":14,"rho":0.5,"median_minutes":87}`. The page states a figure a beta tester can check in one command and find false.

Runners-up, for the record: `?only=day` and `?only=hero` render a completely blank page on both nodes; the observatory's Feed tab, which is the connector registry, shows zero provenance pills; the observatory carries 181 axe colour-contrast violations against 3 on the landing.

**Collisions.**

- Same word, different meaning: `live` means "a source answered this session" in the observatory (`148`), "this cell has enough hourly buckets to claim it" in the node (`app/index.py:81`), and "Commitment" in the landing's `p-live` class.

- Different words, same meaning: `Synthetic proxy`, `SYNTHETIC`, `Synthetic`, `is-mock`, `MOCK ○`.
- A state that is not a state: `index unreachable` is a fetch failure rendered in the same amber as a designed provenance state. Caveat: those four `index.fab.city` fetches were blocked by same-origin policy because I served the file from `127.0.0.1:8790`; from the deployed origin they may succeed. The design point stands whatever the network does — a failed request should not be dressed as provenance.
- A date is not a state: `gauge wall opens 27 Jul`.
- The dashboard's only pill says `Derived`, a seventh word, and it is a static string.

## Four decisions

### 0. Which token canon wins

**The evidence.** Canon A (Claude Design: `#F9F5F2` paper, `#171717` ink, `#E4E2DD` grid, Funnel Sans display, Figtree body, Circular for the wordmark only, radius 8 controls and 14 cards) is implemented in **zero files on zero surfaces**. Its token file exists at `fab-city-design-system/tokens.css` and no surface links it. Canon B (FCI ruling: `#F7F5F1` paper, `#1E1E1E` ink, `#DCD9D3` rule, Circular Std display, Figtree body, Funnel Sans utility, JetBrains Mono data face, square corners) has its paper and ink on **four surfaces across four files** — landing, observatory, node0 with its two children, and `assets/site-chrome.css` — 28 and 163 occurrences. Neither canon's hairline is anywhere in the web repos; all four surfaces use `#d8d3c4` or an alpha ink. Canon B's full stack, including the mono and the square corners, exists in exactly one file, the FAB26 simulator, which is not a web surface.

The dashboard sits outside both, on `#16150F` / `#F4ECE2`, and it does so for a measurable reason: on a `#1E1E1E` ground the ruling's blue is 1.60:1 and its red 3.67:1, while the dashboard's substituted `#3FA9F5` and `#7AC943` reach 7.15 and 8.94 on `#16150F`. The ruling's §1 claim that the three accents "hold contrast on `#1E1E1E`" is false for blue.

**What forces the decision.** Adopting Canon A means changing paper and ink on four surfaces and 191 occurrences to values no shipped file uses. Adopting Canon B means changing one hairline value on four surfaces, swapping IBM Plex Mono for JetBrains Mono, and deciding what to do about 28 distinct radius values. Whichever wins, the dark register needs its own accent triple, because the ruling's does not work on dark.

### 1. The provenance word list

**The evidence.** Seven vocabularies are in production: `{live, partial}` in the node engine; `Derived` alone on the dashboard; `{Connector pending, Synthetic proxy, Calibration required, Commitment}` on the landing's pills with `{LIVE, CACHED, SYNTHETIC, PENDING}` in the prose beside them; `{is-live, is-cached, is-synthetic, is-pending, is-partial, is-mock, is-preview}` in the observatory's CSS rendering at least nine distinct strings including `index unreachable` and `gauge wall opens 27 Jul`; `{live ●, partial ◐, mock ○}` in the ruling. Two of those are coloured green-for-good and red-for-bad, which the ruling forbids by name because the pill "must never look like a verdict".

The one word that must survive is `partial`, because it is the only one the engine computes and the only one that has a rule behind it (`app/index.py:81-82`, a pack cannot claim `live` until it has the buckets). The word that must go first is the landing's `Commitment` in the live-pill green.

### 2. Whether the observatory is frozen and dated, or rebuilt

**The evidence for freezing.** 1,193,673 bytes in one file, 21,344 lines, 189 distinct colours, 28 distinct radius values, 25 distinct font-family values, 124 emoji, 22.8% CSS use on first load, 38.7 s to network idle on Fast 3G, 185 of the 223 axe nodes found across all thirteen views. It has no visible link to node0. It is uncommitted and still growing.

**The evidence for rebuilding.** It is the only surface with a working synthetic-data discipline, and the honesty devices in it are the ones the ruling says to keep. It is also where the landing's only CTA sends every stranger, and it does not currently send them anywhere near a node.

If it is frozen, the landing's CTA has to stop pointing at it first, or the freeze publishes the problem rather than parking it.

### 3. Whether the dark register is allowed for wall and planet views

**The evidence.** The FCI ruling permits a dark register (§1) for "operator workbench data view and observation-adjacent surfaces", and §7 explicitly leaves PLANETAI's own dark register out of the ruling, to be decided separately. So this is an open question by the ruling's own text, not a departure from it.
